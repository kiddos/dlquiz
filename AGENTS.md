# AGENTS.md

Welcome to the **Driver License Quiz (`dlquiz`)** repository! This document provides essential architectural context, project conventions, and operational workflows for AI agents and human contributors working within this codebase.

## 1. Project Overview & Architecture

- **Name / Package**: `scooter_driver_license_quiz` (Application ID: `app.kiddos.dlquiz`)
- **Purpose**: A cross-platform exam simulation and practice application for Taiwan's official Driver's License Written Exam (中華民國交通部公路局筆試題庫).
- **Target Platforms**: Android, iOS, Linux, macOS, Windows, and Web (Flutter Multiplatform).
- **Directory Structure (`lib/`)**:
  - The project uses a feature/layer hybrid modular architecture:
    - `l10n/`: Translation ARB definitions & generated files.
    - `models/`: Domain models (`Question`, `WrongQuestionRecord`) and state management (`QuizState`).
    - `pages/`: UI screens (`selection_page.dart`, `quiz_page.dart`, `review_page.dart`).
    - `utils/`: Helpers (`database_helper.dart`, `question_parser.dart`).
    - `widgets/`: Reusable UI components (`ad_banner.dart`).
    - `main.dart`: Application entry point.
- **State Management & Data Flow**:
  - Uses reactive `StatefulWidget` architectures combined with model state controllers like `QuizState`. No external state management libraries (e.g., Riverpod, Bloc, Provider) are used.
  - Data flows from local SQLite storage (managed by `DatabaseHelper` singleton) and bundled JSON datasets, parsed via `QuestionParser`, into model controllers.
- **Database Storage**:
  - Uses `sqflite` for Mobile (Android / iOS).
  - Uses `sqflite_common_ffi` for Desktop (Linux / Windows / macOS).

## 2. Environment, Code Generation & Build Commands

- **Environment**:
  - Flutter SDK version: `>=3.11.0`
  - Dart SDK version: `^3.11.0`
  - Python 3.12+ (for data extraction & dataset verification).
  - Note: No environment managers (e.g., `fvm`, `mise`) are currently used. Commands should be executed directly via the `flutter` or `dart` CLI.
- **Dependency Management**:
  - Fetch dependencies: `flutter pub get`
  - Add a package: `flutter pub add <package>`
  - Remove a package: `flutter pub remove <package>`
- **Code Generation**:
  - Generate localizations: `flutter gen-l10n`
  - No `build_runner` or `freezed` is used in this project.
- **Build Commands**:
  - Android App Bundle (AAB): `flutter build appbundle --release`
  - Android APK: `flutter build apk --release` (or `flutter build apk --debug`)
  - Linux Desktop: `flutter build linux --release`
  - Windows Desktop: `flutter build windows --release`
  - macOS Desktop: `flutter build macos --release`
- **Dataset Pipeline Scripts**:
  - Install dependencies: `pip install -r requirements.txt`
  - Extract datasets from official PDFs: `python3 scripts/extract_questions_v2.py`

## 3. Testing, Static Analysis & Verification Workflow

- **Static Analysis & Formatting**:
  - Run linting checks: `flutter analyze`
  - Format Dart source files: `dart format --output=none --set-exit-if-changed .`
- **Unit and Widget Tests**:
  - Run all headless Dart unit and widget tests: `flutter test`
  - Run a specific test file: `flutter test test/path/to/file_test.dart` (e.g., `flutter test test/quiz_test.dart`)
  - Note: Device-dependent integration tests (`integration_test/`) do not exist in this project. All tests under `test/` can be executed headlessly.
- **Dataset Verification**:
  - Verify extracted questions format and counts: `python3 test/test_extracted_questions.py`

## 4. Dart & Flutter Coding Conventions

- **Widget & UI Layer**:
  - Prefer creating small, composable `StatelessWidget` and `StatefulWidget` classes over helper methods that return widgets.
  - Extensively use `const` constructors for widgets to optimize rebuilding.
  - Access theme properties contextually via `Theme.of(context)`.
  - All user-facing strings must be localized. Never hardcode strings; instead use `AppLocalizations.of(context)?.<key>`.
- **State & Concurrency**:
  - Use `StatefulWidget`'s standard lifecycle (`setState`, `initState`, `dispose`) for widget-local reactive state.
  - Always verify `context.mounted` across `async` gaps before using `BuildContext` (e.g., when showing SnackBars or dialogs after an awaited Future).
- **Native Interop**:
  - Custom MethodChannels, EventChannels, and Dart FFI bindings are not utilized in this project.

## 5. Agent Guardrails (Do's and Don'ts)

- **DO NOT manually edit generated files**: Never touch files generated by tools (e.g., `lib/l10n/app_localizations*.dart`). If strings change, update `lib/l10n/app_en.arb` and `lib/l10n/app_zh.arb`, then run `flutter gen-l10n`.
- **ALWAYS run static analysis and tests before finalizing**: Execute `flutter analyze` and `flutter test` prior to submitting changes to ensure regressions are avoided.
- **ALWAYS verify the dataset if questions are altered**: If touching data in `questions/v2/`, never manually alter numbering or values. Run `python3 test/test_extracted_questions.py` to ensure dataset integrity. All newly added images must exist in their respective `images/` directory and be registered in `pubspec.yaml`.
- **DO initialize `sqflite_common_ffi` in tests**: When writing tests that interact with `DatabaseHelper`, always invoke `sqfliteFfiInit()` and supply an in-memory database using `DatabaseHelper.instance.setDatabase(db)` in `setUp()`. Close it in `tearDown()`.
- **DO maintain UI navigation accessibility**: Preserve keyboard navigation (e.g., `SelectionPage` listeners waiting for `Enter`) and keep bottom components like `AdBanner` preserved on primary scaffold pages.
- **DO use `flutter pub` to manage packages**: Rely on `flutter pub add` / `flutter pub remove` rather than manually editing `pubspec.yaml` unless pinning specific versions or registering assets.
